# PenLab tablet test plan — 27 Nov 2026

For: the owner (by hand, on the Tab S9) and any agent doing QA. Build under test: `ui/redesign` at the data-safety commit
(`9f1c8e4` or later) plus the Claude AI plugin from `penlab-extras` (`ed8b796` or later).

How to read it: each test says what to do, what should happen, and what counts as a fail. Write the test number and what
you saw for anything that fails. **Part A is the important one** (your notes); B–D are features; E is Omar's overnight work.

## 0. Before you start (5 min)

1. Install both APKs (PenLab release + `ai-release.apk`). If PenLab says the signature differs, stop and ask; don't uninstall.
2. Settings → Plugins: make sure **Claude AI** and **Lecture recording** are on (a reinstall can switch them off).
3. Make a throwaway notebook called **TEST** (A4, lined). Do all writing tests in it, never in a real course notebook.
4. Backup check: `Documents/GraphiteExport` still exists (it is the backup of the 110 imported notebooks).

## What was fixed in this build (for the record)

- **BUG-15** (real, confirmed in code): ink written before a notebook finished loading was wiped by the load and never
  saved. The pen now waits for the load (`InkCanvasView.awaitingLoad`).
- **BUG-14** (real): every open made a new save thread, so a quick close-and-reopen could read the file before the last
  save finished, and the next autosave made the loss permanent; threads also leaked. Now one shared save thread
  (`PageStore.SAVE_THREAD`). Opening a notebook while another is open now saves and closes it first.
- **BUG-16**: the library cover map (Compose state) was changed from a background thread; now on the main thread.
- Checked and **not** bugs: folder rename onto an existing name merges (notebooks are stored by id, nothing lost);
  a failed delete leaves the notebook in place.
